# 历史部署流程与复现说明

这份文档整理自项目早期的“部署说明”文件。它保留了当时的手动建工程方式，供理解旧项目和排查历史问题使用。

> 当前仓库已经提供完整 Gradle 工程。新用户优先克隆仓库并使用 Android Studio 打开根目录，不需要再手动创建工程或逐个替换文件。以下步骤是旧版复现路径，不是当前唯一安装方式。

## 早期手动建工程步骤

1. Android Studio → New Project → Empty Activity (Compose)。
2. Name：TiltFold。
3. Package name：com.tiltfold.demo。
4. Language：Kotlin。
5. Minimum SDK：API 24。
6. Build configuration language：Kotlin DSL。

旧版要求替换以下文件：
- settings.gradle.kts
- 项目级 build.gradle.kts
- app/build.gradle.kts
- app/src/main/AndroidManifest.xml
- app/src/main/java/com/tiltfold/demo/TiltFold.kt
- app/src/main/java/com/tiltfold/demo/MainActivity.kt

创建 Compose 工程时 Android Studio 会自动生成 MainActivity.kt。旧流程要求覆盖模板文件，避免同时保留两套 Activity 入口。

旧版还要求确认 app/src/main/res/values/strings.xml 中 app_name 为 TiltFold。

完成后执行 Gradle Sync，再运行应用。首次同步需要下载 Gradle 插件和 Compose 依赖，耗时取决于网络。

## remember0f() 历史说明

旧版 TiltFold.kt 曾定义：

```kotlin
@Composable
private fun remember0f() =
    androidx.compose.runtime.remember {
        androidx.compose.runtime.mutableStateOf(0f)
    }
```

它只是把 `remember { mutableStateOf(0f) }` 缩写成一个小辅助函数，不是传感器算法，也不是 Android 特殊 API。若读者觉得抽象层级增加了理解成本，可以直接写完整表达式并删除辅助函数。

## 旧工程与当前工程的区别

旧工程是单文件集中实现，包含传感器封装、参数对象和多个 AGSL shader。当前工程拆分了 Activity、传感器输入、纯数学逻辑和测试。旧文档用于保留历史过程，不应把旧文件直接覆盖回当前 main 分支。

## 当前推荐方式

```bash
git clone https://github.com/GSvegetable/iPhone-Duo-Style-Gyroscope-Rotation-Effect.git
cd iPhone-Duo-Style-Gyroscope-Rotation-Effect
```

使用 Android Studio 打开仓库根目录，等待 Gradle Sync，然后运行 app 模块。命令行验证：

```bash
gradle :app:testDebugUnitTest :app:assembleDebug
```

如果构建失败，先检查 JDK 17、Android SDK Platform 35、Gradle 插件下载和网络代理，不要直接随机升级 Kotlin / AGP / Compose 版本。
